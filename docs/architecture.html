01

数据源接入

把数据结构与业务材料变成可用输入

连接与结构采集

只读连接配置、库表字段浏览、DDL 导入。

双路采集：information_schema 与 DDL 解析生成同一份元数据，保留注释、类型和主键。

统一材料库

业务文档、接入 DDL、血缘与任务 SQL 统一选用。

材料共享：已接入的 DDL / 结构快照直接参与建模；业务文档可组合使用，无须重复上传。

结构与文档解析

查看文档正文、表字段结构、解析状态与来源。

按类型解析：SQL 方言解析与文档分段分别处理；保留来源，解析成功后才进入识别。

血缘与关联证据

整理字段依赖、加工表达式、表间 JOIN 与热度。

SQL 补全血缘：sqlglot 解析任务 SQL，合并 DataWorks 导出；热点 SQL 补充关联证据。
交付结构字典 · 材料正文与来源 · 字段血缘与计算口径
02

OntoWing 本体建模

让业务概念与物理表字段建立明确联系

多材料识别与草稿

文档与 DDL 组合生成对象、属性和关系候选。

双向对齐：文档自上而下识别业务语义，DDL 自下而上约束结构；候选附带原文依据。

业务本体编辑

全量本体图，点选类、属性和关系编辑详情。

稳定标识与领域校验：图与详情联动，维护继承、关系方向与基数；草稿变更使检查失效，采用时接入 OntoWing 校验与导出。

R2RML 数据映射

数据表对齐、实体键、属性列与关系 JOIN 编辑。

语义落到物理列：概念绑定表、属性映射列、关系配置 JOIN；键与字段类型必须一致。

模型检查与采用

本体、映射、规则检查，通过后用于字段溯源。

三重核验：OntoWing 领域校验、Morph-KGC 映射实跑、SWRL 与独立 SQL 对账；采用后固定快照。
交付OWL · R2RML · SWRL · 材料依据与模型快照
03

字段溯源智能体

基于本体和 R2RML 回答字段来自哪里

需求理解与上下文

中文问题、多个字段、客户 OCR 文本和页面信息。

模型理解、工具执行：拆解字段并选择字段溯源、截图溯源或规则解释工具；不提供 OCR。

受控语义检索

从业务叫法找到对应的本体属性和源字段候选。

本体约束候选：SemanticIndex 只解析本体与 R2RML；沿“叫法 → 属性 → 物理列”查找。

来源判定与血缘追溯

区分源系统页与中台报表，解释实际取数来源。

多证据判断：同义匹配、页面一致性、样例值核验；中台字段沿任务 SQL 血缘回溯原字段。

结果与依据

原表原字段、计算口径、置信度、证据和历史记录。

事实来自工具：说明中的字段核对工具结果；未找到与歧义明确提示，大模型不可用时退回规则引擎。

本图描述目标产品的功能架构。正式前端已接通真实 MySQL DDL / SQL 的结构与依赖解析、证据草稿、服务端编辑、OntoWing 静态校验 / OWL 与 R2RML 导出、快照采用和语义索引溯源。PDF、多方言、映射实跑与效果评测仍待完成。

工作区账户：首次由用户创建账户，没有默认口令；支持新增、启停、改名、本人改密与退出。所有成员权限相同。密码使用 Argon2id，数据库会话通过 HttpOnly Cookie 与 CSRF 令牌验证；业务接口和导出均需登录。正式应用无预制模型、问题或模拟查询。

现有引擎依据：reference/poc/sgtrace/metadata.py 与 evidence.py 提供结构和 SQL 血缘；wing.py、verify.py、reason.py 提供领域校验、映射实跑与规则核对；semantic.py、qa.py、agent.py 提供语义索引与受控溯源。新版工作台尚未全部接上这些服务。

文档建模参考：OntoWing 的 MaterialDock、材料输入集合、实体 / 关系识别与数据表对齐流程。业务输入按现有一期范围约束，真实生产资料与模型生成仍需集成验收。
