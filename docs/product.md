# 字段溯源工作台：产品功能架构

本设计说明正式产品的模块组成、模块关系、内部功能和关键实现方法。三个模块处于同一个工作台，所有人使用相同功能；没有角色、审批或工单层级。

2026-11-18 用户已确认当前正式工作台交互，作为下一轮开发基线；`product-demo/` 仅保留为历史原型。确认的架构图为同目录的 `architecture.html`：三个产品模块并列展开，功能下直接说明关键方法，顶部和底部显示模块之间的关系。

## 产品目标与当前交互

产品研发的对象是一套**高效、准确、可验证的本体构建方法**，业务目标是字段溯源。本体是方法产物；不以某一版营销域模型的类数和关系数代替产品效果。DDL 与 SQL 揭示存储结构和使用事实，业务含义需要注释、资料及其他证据支撑；不把一张表直接视为一个业务概念，也不把 SQL 高频使用视为语义真实性。

客户主路径保持一站式：**传入材料 → 生成本体与来源映射 → 检查可用范围 → 用于字段溯源**。结构解析、查询归纳、语义对齐和消歧属于方法内部步骤，按需展开；客户无须先写本体、整理金标准或逐项操作分析阶段。待确认项暂不进入采用范围，不阻止证据充分的其他内容继续使用。草稿、检查与采用版本分别管理。

### 工作台页面与交互

页面只保留一个左侧功能菜单，顶部为品牌和账户，不显示固定领域标签、不重复全局业务导航。左栏分组直接列出数据库连接、文档材料、本体模型、溯源问答；进入模型后，在同一左栏显示材料选择、本体画布、校验与采用。删除“全部本体模型 / 全部模型”等重复入口；模型列表中的分组为行内筛选，下方直接展示模型。白色界面、近白画布、深色正文，蓝紫色强调操作和选中状态。

文件接入唯一归属于“数据源接入”：数据库连接采集 DDL，文档材料页负责上传与粘贴。文档页不再常驻大上传区，右上角“新建文档”打开弹窗，下方按行展示名称、类型、原文摘要、版本 / 大小和查看操作。建模页只能选用接入后的文档与结构，不提供文件上传。

建模时可打开“业务流程说明”弹窗手写业务对象、流程及关系。说明按模型保存，不新建材料库文档；生成任务固定该次说明原文、SHA-256 和 `model_context` 来源，历史输入不随说明后改而变化。未启用语义增强时仅作人工核对上下文；开启后参与受候选 / 原文约束的语义增强，仍不自动将新业务假设转成事实。本次是输入交互接通，不等于已实现从自由业务描述自动推导全新业务本体。


| 页面 | 操作方式 |
|---|---|
| 数据源 | 左侧连接列表，右侧连接详情及数据库列表。新建 / 编辑 MySQL 的名称、主机、端口、用户和密码；测试连接读取实际可访问库，支持单选、多选、筛选与全选；保存选择后采集只读 DDL 到材料库 |
| 文档材料 | 右上角新建文档，弹窗上传或粘贴正文，列表逐行展示介绍与原文。支持 UTF-8 SQL / TXT / Markdown；采集的 DDL 直接复用；PDF 正文提取未接通，不显示虚假解析结果 |
| 本体模型 | 单页展示模型，按名称搜索或行内分组筛选，支持新建、命名、改名和移动分组。模型具有独立地址、生成记录、当前草稿与采用快照；新生成版本保留之前的运行记录 |
| 本体画布 | 仅有统一功能左栏，模型功能在同一左栏展开；顶部双排紧凑工具栏，其余主区由完整画布占满。本体类始终用可读卡片展示名称和属性，不用圆点；关系用带名称的有向连线。支持属性展开 / 收起且保留总数、多行卡片按实际高度布局。默认不展示编辑器，点击类、属性或关系弹出编辑窗口，支持对象搜索、缩放、平移、适应画布和全屏；缩放采用绝对比例，密集模型也可放大到可读大小 |
| 溯源问答 | 简单问答输入区，显式选择已采用的本体模型；支持截图附件保存 / 预览，返回字段归属、物理来源、规则置信评分和证据。未知 / 多候选保留证据不足状态 |

连接密码加密保存，API 从不回传密码；本地密钥位于存储目录的 `.connection-key`，备份须与数据库和材料存储一起保留。只调用元数据查询与 SHOW CREATE，不运行客户取数 SQL，不创建或修改源库对象。连接测试不等于已保证数据库账号只读，源库权限由数据库管理员授予。

问答当前仍是采用版本内的字段 / 同义名称匹配，尚未接入自由问题理解及自动读图。截图经过类型、大小和登录鉴权校验后保存在本地，不向大模型发送，不自动提取表头或样例行；用户仍需输入字段名或提供客户 OCR 文本。规则置信评分依据明确名称匹配、同义匹配及导出映射核对，不是校准后的业务准确率；歧义和未找到不填虚假百分比。近期问答暂存于当前页面会话，刷新后不会恢复；永久对话历史仍待实现。

正式前端 `frontend/` 当前已接通以下真实服务闭环：

| 操作 | 当前实现 |
|---|---|
| 准备材料 | 文本上传持久化、材料版本和 SHA-256、DDL / SQL / 文档分别标识；原始正文可回看 |
| 结构与查询分析 | MySQL DDL 注释 / 主键 / 外键；SELECT、CTE、视图及 INSERT SELECT 字段依赖；完整查询上下文、条件和聚合；冲突与未知字段不猜测 |
| 语义增强 | 用户显式启用后调用配置的模型；只能使用已有候选及其名称证据，不改变结构和物理映射。文档新假设不自动采用 |
| 本体与证据 | 完整本体图、证据位置、计算口径与歧义，类 / 属性 / 关系编辑保存到服务端；并发修订冲突拒绝覆盖 |
| 验证并采用 | 真正调用 OntoWing `validate_editor` / `render_member`；固定草稿摘要和 OWL / R2RML 产物；不可变模型快照及下载 |
| 字段溯源 | 解析采用版本 OWL / R2RML，查找直接字段和核对过的计算依赖；未知与多口径不返回猜测答案 |

当前方法以表结构作为候选锚点，业务概念重组、跨表语义归并和领域定义仍须后续方法验证；不能把“每表一个候选”称为完整业务本体。热点 SQL 的频率只用于将来候选排序，不等于语义真实。语义增强只允许候选自身的结构 / SQL 名称，文档中的新定义和关系仍需人工确认。

验证边界：本轮已实测 MySQL 持久化、真实 HTTP、配置的模型语义建议、OntoWing 静态校验与导出及前端刷新恢复；这些属于功能验证，不是效果准确率。Morph-KGC 物化、业务 SQL 对账和 PUDL / SimBench / CIMHub / 客户留出集评测尚未执行。PDF、其他 SQL 方言、动态 SQL、异步调度与自动恢复尚未接通。分析在隔离子进程中有 90 秒上限；失败 / 未知的模型调用不会自动重试。

正式运行入口移除了内置示例材料、固定问题、模拟查询与模拟校验。空数据库从创建账户、上传材料开始；展示的材料、草稿和采用模型全部由正式后端持久化并恢复。合成夹具保留在测试目录，独立原型不参与正式运行。

登录与账户管理作为工作区基础功能：首次使用创建首个账户，没有默认账号口令。成员可新增账户、修改名称、启用或停用其他账户，修改自己的密码并退出登录。所有账户共享工作区与相同功能，包含账户管理；不增加业务角色、审批或工单。账户不能停用自身，避免把所有成员锁在工作区之外。密码采用 Argon2id 散列存储，随机会话令牌只在 Cookie 中传递，数据库存储令牌摘要；会话 12 小时到期。业务接口、文档和导出均验证会话；状态、登录、首次初始化和健康检查为明确公共入口。写入接口校验 CSRF 令牌和来源，失败登录按账户与本机来源计数限流；账户变更写审计事件。停用、退出和改密会撤销对应会话。当前不提供自助注册、邮箱找回、SSO 或复杂权限矩阵。

“完整本体”展示当前草稿全部类、属性及关系，包含待确认的孤立属性和关联候选。点击类节点、属性行、关系连线或名称，弹出对应编辑窗口：类可维护名称、说明、同义叫法和父类；属性可维护名称、归属、类型、单位和同义叫法；关系可维护名称、说明、起点 / 终点、方向、基数、对称 / 传递 / 至多一个终点特性。支持缩放、平移、适应画布、全屏、对象目录搜索和键盘选择。

本体编辑以稳定 ID 维护引用，改名不破坏关系和字段映射。保存会递增草稿修订并使原检查失效，不改已采用版本和历史回答。循环继承、悬空端点、同类属性重名等基础错误会被拒绝；仅修改显示名不会消除候选歧义。物理来源、计算口径和原始证据在此面板只读，人工修改另行标记；真实模式已接入 OntoWing 静态校验与导出，物理映射与证据仅可读。当前支持现有对象编辑，新增 / 删除尚未实现。

## 模块一：数据源接入

职责：把数据库结构和业务、技术材料变成建模与溯源能够使用的输入。

| 内部功能 | 用户可以做什么 | 实现方法 |
|---|---|---|
| 连接与结构采集 | 配置只读连接，浏览库、表、字段；数据库无法直连时导入 DDL | `information_schema` 与 DDL 方言解析产生统一元数据，包括类型、注释、主键与空值约束 |
| 统一材料库 | 上传或粘贴业务文档、DDL、DataWorks 血缘、任务 SQL；在建模时组合勾选 | 文档、接入 DDL、结构快照共享材料入口，不要求重复上传；保留来源与解析状态 |
| 结构与文档解析 | 查看正文、表字段结构和解析问题 | 结构走 SQL 解析，文档走正文分段；PDF 交给文本解析服务，扫描图不做 OCR；未解析成功的材料不进入识别 |
| 血缘与关联证据 | 维护页面背后的中台表、任务和原表字段依赖 | `sqlglot` 从任务 SQL 提取投影、派生表达式与 JOIN，合并 DataWorks 导出；热点 SQL 补充使用热度和关联证据 |

特色在于**结构来源可替换、材料入口统一、SQL 代码补足血缘**。字段注释和名称约定可以辅助构建，但推断必须注明证据来源，不能与明确的任务代码证据混为一谈。

输出给建模模块：结构字典、解析后的文档、选定材料集合及来源引用。输出给智能体：字段血缘、计算表达式、JOIN 和页面用表证据。

## 模块二：OntoWing 本体建模

职责：提供从原始 DDL、SQL 和资料构建本体的方法，把有证据的业务语义与物理表字段关联起来，形成智能体可以使用的本体和映射。

| 内部功能 | 用户可以做什么 | 实现方法 |
|---|---|---|
| 多材料识别与草稿 | 同时选择业务文档、已接入 DDL、结构快照、热点 / 任务 SQL，生成并预览对象、属性和关系 | 按材料类型确定性解析结构、字段依赖、聚合、过滤与粒度，再进行多证据语义对齐；OntoWing 输入适配保留材料版本和依据，不把 SQL 简单当成普通业务正文 |
| 业务本体编辑 | 修改对象、属性、上下位关系、同义叫法和业务规则，浏览关系图 | 复用 OntoWing 编辑器及其领域模型；识别结果先追加到草稿，由用户核对，不以重新生成覆盖已有编辑 |
| R2RML 数据映射 | 将对象对齐到表，维护实体键、属性列和关系 JOIN | 建立“概念—表绑定、属性—物理列、关系—JOIN”的映射；实体键、父绑定键覆盖、属性所属概念和类型一致性需要校验 |
| 模型检查与采用 | 检查本体、映射、规则，采用可用结果供智能体查询 | OntoWing `validate_editor` 与 `render_member`；导出 OWL、R2RML、SWRL；测试数据上用 Morph-KGC 运行映射、检查悬空引用；SWRL 结果与独立 SQL 对账 |

特色在于**业务语义与数据结构双向对齐，编辑器规则、实际映射运行与独立 SQL 相互核对**。模型采用后固定本体、映射与规则快照，编辑草稿不会立即改变智能体结果；历史回答保留原快照的引用。

输出给智能体：已采用的本体、R2RML、规则及其来源依据。OWL / R2RML 是查询的事实约束，不是可绕过的辅助说明。

## 模块三：基于本体和 R2RML 的字段溯源智能体

职责：把业务人员的中文字段或取数需求定位到原表原字段，并说明实际来源和计算口径。

| 内部功能 | 用户可以做什么 | 实现方法 |
|---|---|---|
| 需求理解与上下文 | 输入中文问题、多个字段或客户 OCR 文本，补充系统与页面上下文 | 大模型拆解需求并选择工具；OCR 只接收客户提供的文本，不提供图片识别；样例行留在本地核验链路，不发给大模型 |
| 受控语义检索 | 查询某字段、截图表头或业务分类规则 | `trace_field`、`trace_screenshot`、`explain_rule` 三类工具；`SemanticIndex` 解析本体与 R2RML，沿“业务叫法→属性→物理列”检索，字段候选不直接来自 DDL |
| 来源判定与追溯 | 区分源系统页面与中台报表，解释同义、歧义和计算字段 | 同义词匹配、页面多数系统/多数表一致性、可用样例值核验；中台字段沿 DataWorks 与任务 SQL 血缘回溯到原系统，保留派生表达式与路径 |
| 结果与依据 | 查看 `schema.TABLE.COLUMN`、来源清单、计算口径、置信度、证据链；保存并查找历史记录 | 结构化结果来自工具；大模型说明中的字段与工具结果比对；证据不足时请求上下文或提示未找到；大模型失败时使用规则引擎回退 |

特色在于**大模型负责理解，工具负责事实；语义索引确定可选字段，证据链确定本次页面的实际来源**。置信度表达证据强弱，不能当作人工确认或准确率；同义字段是可接受的等价候选，不自动替换页面实际来源。

## 模块之间的关系

| 关系 | 交付内容 | 如何使用 |
|---|---|---|
| 数据源接入 → OntoWing 建模 | 结构字典、业务文档、DDL、选定材料集合 | 形成识别输入、候选证据和映射约束；已经接入的 DDL 可直接选用 |
| OntoWing 建模 → 溯源智能体 | 已采用的本体、R2RML、SWRL 和快照引用 | 约束候选字段与规则解释；草稿编辑不直接影响当前问答 |
| 数据源接入 → 溯源智能体 | 中台血缘、任务 SQL 表达式、JOIN、热点 SQL 证据 | 用于页面实际来源判定和原系统回溯；不能据此绕开本体/R2RML 的源字段候选约束 |
| 溯源智能体 → 用户补充上下文 / 建模维护 | 未覆盖字段、歧义候选、缺失材料提示 | 用户可补充页面信息或转入材料与建模页维护；不引入审批队列，不自动修改本体 |

## 当前研发交接与下一轮

本轮交付基线包含单侧栏、统一文档接入、数据库连接与多库采集、独立具名模型、模型业务流程上下文、卡片画布和编辑、采用版本选择与字段结果。正式材料、模型、说明和快照由后端持久化；问答历史仍仅页面会话。数据库迁移到 `0007_model_context`，升级前先备份；连接凭据恢复还依赖存储目录的 `.connection-key`。

下一轮按以下顺序推进，仍维持当前已确认的交互：

| 优先方向 | 尚需实现 | 验收依据 |
|---|---|---|
| 本体构建方法 | 业务流程 / 文档与结构 / SQL 的证据对齐、概念重组、候选歧义与人工修订的可靠衔接 | 引用可定位、物理映射不猜测，生成与修改均保留版本；独立专家语义核验和留出集评测 |
| 受控溯源问答 | 自然问题理解、工具调用、澄清、永久会话记录；明确截图附件与表头文本的衔接 | 源字段候选全部来自所选已采用 OWL / R2RML；未知和歧义不编造；历史回答可还原所用快照 |
| 映射与效果验证 | 正式服务调用 Morph-KGC、独立 SQL 对账、100 题和新增留出集、评分校准 | 映射实际执行结果与独立答案核对，公开覆盖率、准确率和未验证项；不得用规则评分替代评测 |
| 工程交付 | 解析格式、异步任务恢复、部署及客户环境验收 | 出错能恢复，不返回假成功；本地回归通过不能替代客户验收 |

这份待办是研发交接，不代表上述能力已具备，也不更改现有不提供 OCR、不发送截图样例行等业务边界。

这是目标产品的功能架构，不能据此认定所有功能已在新版前端连通。
