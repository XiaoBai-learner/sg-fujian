# 字段溯源：已确认交互原型

本目录保留用户确认的产品形态，作为正式开发的交互验收参照。正式代码位于仓库根目录的 `frontend/` 与 `backend/`；不要在这里继续扩展生产后端。

仅保留三个入口，所有人使用同一套功能：

1. **数据源接入**：管理连接配置、浏览表结构、添加 DDL、血缘、任务 SQL 和业务文档。
2. **OntoWing 本体建模**：统一选用业务文档、接入 DDL 和结构快照，生成草稿预览，确认后追加到现有编辑器；直接复用对象属性、关系图、R2RML 管道和规则编辑器。
3. **字段溯源智能体**：输入问题或 OCR 文本，查看源表原字段、计算口径和可展开依据。

默认进入溯源对话。左侧是新建溯源、数据源接入、本体建模和历史记录，右侧是当前工作区。三个模块使用同一个工作台外壳，参考 DeepSeek Harness 的留白和居中输入区。采用暖白底、浅蓝侧栏、深色文字；蓝色用于主要操作，青绿用于可用状态，紫色用于本体和文档。

历史记录可搜索、回看；新建溯源不会删除已有结果。桌面侧栏可折叠，窄屏以抽屉导航。没有角色切换、需求工单、复核队列和审核发布。

## 运行

```bash
cd product-demo
npm ci
npm run start
```

打开 <http://127.0.0.1:4180/agent>。另外两页为 `/sources` 和 `/modeling`。旧 `/workbench`、`/knowledge/*` 等链接自动进入对应的新模块。

依赖旁边的 `../../ontowing/frontend/src` 源码，与现有项目的引用方式相同。Vite 可用 `ONTOWING_FRONTEND` 配置源码目录。

```bash
npm test         # Node >= 22.18；材料读入、DDL 草稿、追加隔离、快照和拒答检查
npm run build    # TypeScript + Vite
npm run preview  # 构建后预览；与 start 使用同一端口，二者只运行一个
```

页面必须通过本地 HTTP 服务打开，不能双击 `index.html`。

## 原型边界

页面操作和编辑可用，连接配置、材料文本、模型与对话在浏览器本地保存。它尚未执行真实数据库连接、OntoWing 后端校验、TTL 导出或大模型推理，不保存数据库账号与口令。

建模页可选择文件、拖拽文件或粘贴正文。TXT/MD/SQL 读取实际正文；接入页也保留 CSV/JSON。每份材料上限 1 MB，UTF-8。PDF 仅登记，显示“待后端解析”，不能作为已解析输入参与生成；不做 OCR。

接入的结构快照和 DDL 与业务文档使用同一个勾选列表，无须重复上传。基本 `CREATE TABLE` 的本地预览保留字段注释、类型和主键；未声明库名时提示补充 R2RML。当前未实现完整方言、外键推断和任意文档识别；业务文档仅按营销域示例词汇预览。不能把本地预览当作 OntoWing 的真实智能识别。

生成结果先供查看，再“追加到当前草稿”，保留现有定义；新增 DDL 表同步进入本地目录，便于继续编辑映射。生成后尚未采用的草稿不会改变智能体当前快照。遇到当前草稿变化，拒绝采用过期预览。

参考代码：`../../ontowing/frontend/src/product/documents.tsx` 的 `MaterialDock`、`modeling-input-set.ts` 和 `modeling-editors/reference-inputs.tsx`。OntoWing 按材料正文、实体识别、关系识别和数据表对齐推进；本前端保留这条路径的简洁交互，生产接入时采用正式后端任务及材料身份。

`src/services/workspace.ts` 中的查询仅通过当前应用的本体属性与管道映射模拟检索。后续应替换为 `sgtrace.semantic.SemanticIndex` 对 OWL/R2RML 导出文件的真实检索。不能把这段浏览器模拟当作生产溯源引擎。

`src/services/wingCatalog.ts` 为 OntoWing 编辑器提供本地模拟目录，仅拦截同源的两个指定目录 GET 路径。后续由实际数据源目录接口替换。

`检查模型` 是本地基础检查；`用于字段溯源` 固定当前本体、映射、规则快照。编辑尚未应用时不会改变当前智能体；重新提问时采用最新应用快照。
