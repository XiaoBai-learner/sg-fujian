# 营销域建模与字段溯源试用包 v1

先用 `inputs/` 的四份材料在正式平台建模、编辑、检查并采用，再使用独立的 100 道题测试。整套数据来自项目既有营销域合成数据，具有已知的表结构与生成口径；不是真实客户数据，也不是独立客户留出集。

## 本机已经准备好

| 内容 | 规模 |
|---|---|
| 原始系统 | 营销 `yx186`、采集 `cjxt`、客服 `kf95598` 的隔离副本 |
| 源表 | 16 张，113 列；客户、单位、联系人、计量点、电表、抄表、应收、缴费、采集、工单、回访 |
| 本地数据 | 90,581 行，复用原确定性生成器，完整关联数据，不只是表结构 |
| 血缘 | 16 个 ODS 同步视图、21 个 DWD/DWS/ADS 任务视图 |
| 热点 SQL | 原合成日志 Q001–Q022，保留模拟 90 天执行次数 |
| 测试题 | 60 道直接字段、20 道计算字段、10 道同名歧义、10 道材料未覆盖 |

本地 MySQL 库：

- `sgtrace_trial_yx186`：9 张表。
- `sgtrace_trial_cjxt`：5 张表。
- `sgtrace_trial_kf95598`：2 张表。
- `sgtrace_trial_platform`：37 个只读视图。

原有 `yx186`、`cjxt`、`kf95598`、`sgfj_dataplatform` 与产品库 `sgtrace_product` 未被本脚本修改。账号读取根目录忽略的 `.env`，本包没有密码。

## 你在平台上怎么操作

1. 在项目根目录的两个终端分别执行 `make api`、`make web`，打开 <http://127.0.0.1:5173>，首次创建账户，之后登录。
2. 进入「本体建模」或「数据源接入」，取消选择上次恢复的旧材料。正式产品不内置试用材料，请按下步自行上传。
3. 一次上传 `inputs/` 中以下四个文件，并只选择这四份：

   | 文件 | 用途 |
   |---|---|
   | `01_source_ddl.sql` | 16 张原表的 MySQL DDL，保留原始主键、类型、已有注释，不补造外键 |
   | `02_lineage_views.sql` | 原 ODS 同步及 DataWorks 任务 SELECT 的只读视图形式，用于追溯上游 |
   | `03_hot_queries.sql` | 原有热点日志，补全本次隔离库名 |
   | `04_report_fields.sql` | 按既有中台列注释生成中文展示查询，给出客户页面使用的字段名 |

4. 点击生成。第一轮可以关闭「模型语义增强」，获得确定性的结构/SQL 基线；第二轮可开启增强做对比，分别记录采用的快照 ID。
5. 在完整本体图中检查类、属性和关系。点击对象可编辑；「字段证据」与「映射」可查看出处。SQL JOIN 只是关系候选，尚未确认的关系和跨对象计算可能不会进入采用范围，应按实际结果记录。
6. 运行校验，检查错误、警告及导出损失，然后点击采用。
7. 进入「字段溯源智能体」，从 `evaluation/questions.csv` 的 **`field` 列**复制待查字段。
8. 建模结束后再查看标准答案，或运行下面的批量测试。

SQL 由建模服务解析，不会执行到业务源库。试用脚本只在上述隔离 MySQL 库中执行已知合成 SQL，以核对输入材料与标准答案。

四份材料在打包检查时已解析成功，OntoWing 静态校验通过。少量常量输出没有物理来源，会明确报告而不生成字段映射。实际生成可能受你选用的材料、语义增强与人工修改影响；静态通过不等于准确率。

## 100 道题和标准答案在哪里

| 文件 | 内容 |
|---|---|
| `evaluation/questions.csv` | 可直接查看的 100 道题，含完整问题、待输入字段和业务页面上下文 |
| `evaluation/questions.json` | 相同问题的机器可读版本，不含答案 |
| `evaluation/answer_sheet.csv` | 空白答题记录表，记录平台原始回答与人工判断 |
| `evaluation/gold/answers.csv` | 标准来源、预期状态、表达式、当前层过滤/分组和说明 |
| `evaluation/gold/answers.json` | 另含逐层血缘、完整原表 SQL、视图核对 SQL，可追查上游全部口径 |
| `manifest.json` | 来源文件摘要、输入/题目/答案 SHA-256、表清单与版本 |

例如：

- 应收电费明细的「应收金额」→ `sgtrace_trial_yx186.A_RCVBL_FLOW.RCVBL_AMT`。
- 抄表示数明细的「抄见电量」→ `R_READ.THIS_READ`、`R_READ.LAST_READ`、`D_METER.T_FACTOR`；按 `(本次示数 - 上次示数) × 倍率` 四舍五入到两位，并保留任务中的 JOIN。
- 只问「联系电话」→ 联系人手机与工单联系电话都是合理候选，需要系统/页面上下文。
- 「变压器油温」→ 本次材料未覆盖，应未找到，不应给出猜测列。

**只上传 `inputs/`，题目、答案、答题表和 manifest 不作为建模材料。** 题目并非复用原开发集/留出集问题；答案沿用原生成定义的独立完整血缘推导，不读取本次本体或智能体输出。80 道可定位题均提供可执行 SQL，并在本地 MySQL 比较视图结果与展开到原表的查询结果。其余 20 道核对同名候选集合或材料缺失边界。

## 建模后批量测一次

在项目根目录、正式后端已启动并已采用本次模型后运行：

```bash
.venv/bin/python trials/marketing_v1/run.py evaluate
```

也可明确固定某次采用的快照：

```bash
.venv/bin/python trials/marketing_v1/run.py evaluate --snapshot-id YOUR_SNAPSHOT_ID
```

脚本先提示平台账号与密码（密码隐藏输入），登录并获得会话和 CSRF 令牌，结束后退出。评测只发送字段名和同一个快照 ID，不发送标准答案，不上传材料，不建模，不修改模型。100 次调用始终使用同一个快照；失败或超时计错，不从分母剔除。报告保存在忽略的 `artifacts/marketing-trial/evaluation-时间.json`，包含每题实际答案与分组得分。

计分规则：

- 直接字段：状态、类型、原表字段集合全部一致。
- 计算字段：状态为已定位、类型为计算字段、物理依赖集合完整一致，不能只命中其中一列。
- 同名歧义：返回歧义且完整列出标准候选集合；只说“歧义”而没有候选不计对。
- 未覆盖：返回未找到，且没有猜测来源或候选。
- 计算表达式、过滤、JOIN 和粒度另行人工核对 20 道计算题；自动来源分数不代表计算口径已经正确。

标准答案的 `sources` 指输出值的列依赖；过滤条件、分组键和 JOIN 键作为影响计算的上下文，保存在完整核对 SQL 中。两者分别核对，不能只看源列相同就认定口径相同。

当前正式接口是**字段名查询**，尚未接通完整自然语言需求和页面上下文消歧。完整问题保留了真实任务场景，但自动测试只输入 `field`，报告标为 `field_only_no_page_context`。有上下文的题目仍按指定页面的标准来源判分，信息无法传入而产生的歧义会体现为缺项，不修改标准答案迁就实现。人工试用时直接输入整句问题，可能得到未找到；这应作为自然语言能力尚未接通的记录。不要把此分数称为完整自然语言智能体准确率。

这是一套可重复的产品试用集，适合找问题和比较版本。看到错题并据此修改方法后，本集成为回归集，应另外建立客户留出集评估泛化效果。

## 重新准备或核对

当前本机已经完成建库和载入，无需再次安装。换到全新本机环境时：

```bash
.venv/bin/python trials/marketing_v1/run.py install-mysql
.venv/bin/python trials/marketing_v1/run.py verify-mysql
```

安装仅允许本机 MySQL；四个试用库中任意一个已存在就停止，不执行 DROP 或覆盖。建表 DDL 会被 MySQL 自动提交，安装中途失败可能保留部分试用库；脚本不会自动清理，先检查原因再处理该隔离库。

重新生成材料与题目：

```bash
.venv/bin/python trials/marketing_v1/build.py
```

该命令只重建本包的生成文件，不执行 MySQL，也不触碰原 PoC 数据。`build_inputs` 只读取原输入与数据生成定义；标准血缘只在 `build_answers` 中读取。请保留本次提交和摘要，不在同一轮测试中改题、改答案或重新构建后混用成绩。
